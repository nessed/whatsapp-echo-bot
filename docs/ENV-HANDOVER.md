# Handover checklist — what the second developer changes

For the person receiving a copy of someone else's `.env`.

The short version: **keep Supabase and DeepSeek, replace everything else.**
The Meta, ngrok and n8n values in the file you were given belong to the other
developer's accounts and will not work from your machine.

---

## For the sender: only 6 values need to travel

You replace every Meta, ngrok and n8n value anyway, so sending them is exposure
with no benefit. The cleanest handover is a trimmed file containing only:

```bash
SUPABASE_URL=
SUPABASE_SERVICE_KEY=
DEEPSEEK_API_KEY=
DEEPSEEK_API_BASE=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_MAX_TOKENS=512
```

Send it over something private and expiring — not a commit, not a group chat,
not a screenshot. `SUPABASE_SERVICE_KEY` bypasses every row-level security rule
in the project; treat it like a database root password.

If you send the whole file instead, everything marked **REPLACE** below is
now a credential you've shared unnecessarily — rotate it if that matters to you.

---

## 1. The `.env` file

Work top to bottom. Every row is either **KEEP** (shared, leave exactly as
received) or **REPLACE** (yours).

### Meta / WhatsApp — REPLACE all

| Variable | Action | Where to get it |
|---|---|---|
| `META_ACCESS_TOKEN` | **REPLACE** | Your own permanent System User token, scopes `whatsapp_business_messaging` + `whatsapp_business_management`. Confirm `expires_at` is `0`. |
| `META_PHONE_NUMBER_ID` | **REPLACE** | Your app's WhatsApp → API Setup screen. The numeric **id**, not the phone number. |
| `META_APP_ID` | **REPLACE** | Your app → Settings → Basic. (Likely empty in the file you got — it was never needed for P1.) |
| `META_APP_SECRET` | **REPLACE** | Same screen. Also likely empty. |
| `WEBHOOK_VERIFY_TOKEN` | **REPLACE** | Invent your own random string. You type the same value into your Meta webhook config. |
| `META_API_VERSION` | **KEEP** | `v25.0`. Not a secret — a pinned, verified API version. |

### ngrok — REPLACE

| Variable | Action | Where to get it |
|---|---|---|
| `NGROK_AUTHTOKEN` | **REPLACE** | Your own ngrok account → Your Authtoken. Claim a free static domain while you're there, or your URL changes on every restart and you must re-verify the Meta webhook each time. |

### n8n — REPLACE

| Variable | Action | Where to get it |
|---|---|---|
| `N8N_URL` | **REPLACE** | Your ngrok HTTPS URL, no trailing slash. |
| `N8N_API_KEY` | **REPLACE** | Generated by *your* n8n instance (Settings → API). The other developer's key is useless to you. |
| `N8N_WEBHOOK_BASE` | **REPLACE or leave empty** | Optional. Only if you want the fake-payload script to go through ngrok instead of localhost. |

### Supabase — KEEP, do not touch

| Variable | Action | Notes |
|---|---|---|
| `SUPABASE_URL` | **KEEP** | Shared project. |
| `SUPABASE_SERVICE_KEY` | **KEEP** | Shared service-role key. Bypasses all row-level security — never commit it, never put it in a workflow export. |

### DeepSeek — KEEP, do not touch

| Variable | Action | Notes |
|---|---|---|
| `DEEPSEEK_API_KEY` | **KEEP** | Shared prepaid balance. Every call spends it. |
| `DEEPSEEK_API_BASE` | **KEEP** | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | **KEEP** | `deepseek-v4-flash` |
| `DEEPSEEK_MAX_TOKENS` | **KEEP** | `512`. Cost control — leave it. |

### The allowlist — REPLACE

| Variable | Action | Notes |
|---|---|---|
| `ALLOWED_WHATSAPP_NUMBER` | **REPLACE** | **Your** handset. Digits only, no `+`, no spaces. Include the country code. |

> ⚠️ Changing this in `.env` does **not** change the bot's behaviour. The
> allowlist the workflow actually enforces is hardcoded in an n8n node — see
> section 2. Set it here anyway so the file stays honest.

### Shopify (P2 groundwork) — decide together

| Variable | Action | Notes |
|---|---|---|
| `SHOPIFY_STORE_DOMAIN` | **Ask** | Points at the other developer's dev store (`Kavern`). Share it or create your own — agree before either of you builds against it. |
| `SHOPIFY_CLIENT_ID` | **Ask** | Same. |
| `SHOPIFY_CLIENT_SECRET` | **Ask** | A real secret belonging to their app. |
| `SHOPIFY_ADMIN_API_VERSION` | **KEEP** | `2026-07`, pinned. |

None of these are used by P1. Ignore them until you start P2.

## 2. Inside n8n — the part `.env` does not cover

**The workflow never reads `.env`.** That file only feeds the scripts in
`scripts/`. The running bot gets its configuration from values hardcoded in
nodes plus n8n's encrypted credential store.

So after **Workflows → Import from File →**
`workflows/whatsapp-deepseek-assistant.json`, change these by hand:

### 2a. Three hardcoded literals

| Node | Field | Currently | Change to |
|---|---|---|---|
| `Allowed Sender` | rightValue | `923000413777` | your handset, digits only, no `+` |
| `Send WhatsApp reply` | URL | `https://graph.facebook.com/v25.0/1303482916173126/messages` | your `META_PHONE_NUMBER_ID` in place of that number |
| `Send text-only reply` | URL | same id | your `META_PHONE_NUMBER_ID` |

> When editing `Allowed Sender`, the right-hand value must be in **Fixed** mode,
> not Expression. An Expression-mode field always stores a leading `=` that no
> amount of retyping removes, and the comparison then silently never matches.
> The `fx` badge on the field's left edge tells you which mode you're in.

**Leave alone:** the seven Supabase nodes (`Log to Supabase`,
`Claim assistant run`, `Load history`, `Log outbound`, `Complete run`,
`Log text-only reply`, `Mark run failed`) and `DeepSeek chat`. Those point at
the shared services and are already correct.

### 2b. Three credentials — create your own

The export carries credential **ids and names only**, never secret material, so
none of these arrive with the file. Create them under **Credentials → New**,
then open each node that needs one and select it.

| Name | n8n type | Value |
|---|---|---|
| `Supabase (messages)` | Supabase API | Host = `SUPABASE_URL`, Service Role Secret = `SUPABASE_SERVICE_KEY` (both **shared**) |
| `DeepSeek account` | DeepSeek | API Key = `DEEPSEEK_API_KEY` (**shared**) |
| `Meta WhatsApp` | Header Auth | Name = `Authorization`, Value = `Bearer <your META_ACCESS_TOKEN>` (**yours**) |

Keep the names exactly as written — the imported nodes reference them by name.

> The `Meta WhatsApp` one is worth creating via the API rather than pasting. A
> truncated paste or a missing `Bearer ` prefix produces n8n's generic
> `Authorization failed - please check your credentials` with a token that is
> completely fine, and n8n encrypts credential values so you can never inspect
> what it stored. Exact curl command is in [SETUP.md](SETUP.md) step 6b.

### 2c. Activate, and republish after every later edit

n8n serves the last *activated* version, not your draft. Edit a node without
republishing and the live webhook keeps running the old version — the classic
symptom is a 404 "not registered for POST requests" while the node sits plainly
on the canvas.

## 3. In the Meta dashboard

1. Create your own app, add the **WhatsApp** product, get your free test number.
2. **Add your handset as a verified recipient.** The test number can only send
   to numbers you explicitly add.
3. Webhook config → callback URL `<your ngrok URL>/webhook/whatsapp`, verify
   token = your `WEBHOOK_VERIFY_TOKEN`.
4. **Tick the `messages` field.** Meta auto-subscribes `account_update`,
   `calls` and others on save, but *not* `messages`.
5. **Subscribe your app to your WABA** — there is no dashboard button:
   ```bash
   curl -X POST "https://graph.facebook.com/v25.0/{WABA_ID}/subscribed_apps" \
     -H "Authorization: Bearer $META_ACCESS_TOKEN"
   ```
   Skip this and real messages silently never arrive while every indicator
   stays green. Meta's "Test" button does not catch it — it bypasses the real
   delivery path.

## 4. Confirm it worked

```bash
npm run verify:meta       # your token — sends one real message to your handset
npm run verify:supabase   # shared DB — insert and read back
npm run verify:deepseek   # shared key — one completion
npm run test:webhook      # fake payloads at your own local n8n
```

> If `verify:meta` reports success and no message arrives, that's the 24-hour
> window, not a broken token. Free-form sends to a number that hasn't texted
> your test number first return HTTP 200 with a valid message id and are then
> silently never delivered. Text your test number from the handset, then re-run.

Then text your own test number and expect a DeepSeek reply, plus an `in` row,
an `out` row, and an `assistant_runs` row at `status: completed`.

Finally, **delete your synthetic test rows** from `messages` and
`assistant_runs`. The bot feeds the last 10 stored messages to DeepSeek as
conversation history. The fake-payload script uses `447700900123`.

## Quick reference

**REPLACE:** `META_ACCESS_TOKEN`, `META_PHONE_NUMBER_ID`, `META_APP_ID`,
`META_APP_SECRET`, `WEBHOOK_VERIFY_TOKEN`, `NGROK_AUTHTOKEN`, `N8N_URL`,
`N8N_API_KEY`, `N8N_WEBHOOK_BASE`, `ALLOWED_WHATSAPP_NUMBER`

**KEEP:** `META_API_VERSION`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`,
`DEEPSEEK_API_KEY`, `DEEPSEEK_API_BASE`, `DEEPSEEK_MODEL`,
`DEEPSEEK_MAX_TOKENS`, `SHOPIFY_ADMIN_API_VERSION`

**ASK:** `SHOPIFY_STORE_DOMAIN`, `SHOPIFY_CLIENT_ID`, `SHOPIFY_CLIENT_SECRET`

**Outside `.env`:** 3 node literals, 3 n8n credentials, 5 Meta dashboard steps.
